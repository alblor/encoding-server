- BUG-113 (2026-11-03, complete): the secret lifecycle script. `scripts/secure_secret_lifecycle.sh` used `((count++))`, which returns 1 under `set -euo pipefail`, so `shred` aborted after the first secret and four stayed on disk (QC F1, HIGH, already in HEAD). Also: the macOS `dd` fallback got `count= 44` from a padded `wc` (F1b), the `gpu-up` and `gpu-down` follow-on (F1c), the "encrypted backup" used a random passphrase that was thrown away, so the archive was unrecoverable and the passphrase showed in `ps` (F4, MEDIUM), `generate_secrets.sh` printed the first 8 characters of each secret (F5, LOW). Not fixed: the API container cannot chown secrets, no CHOWN (F6, LOW/info); QC re-scored it as informational and it stays so, behaviour unchanged since before this branch. Fixes: counters are `x=$((x + 1))`, the dd count is stripped, the backup is opt-in via `SECRET_BACKUP_PASSPHRASE_FILE` (`-pass file:`, umask 077; without it no backup and a notice), `generate_secrets.sh` prints a length. Tests: `tests/unit/test_secret_lifecycle.py` (4, in `RESTORE_HOST_TESTS`).
- BUG-114 (2026-11-03, complete): `needs_source` left out `fidelity.glow` (F2, MEDIUM, same class as BUG-091), and a valid but wrong ONNX as `HEAD_MODEL` failed with a cryptic broadcast error (F3, MEDIUM). Fixes: `recipe_needs_source()` in `restore_worker/pipeline.py` (includes glow) replaces the inline expression; `heads.py` `_tile` validates the model output shape and raises `HeadModelMissing`. Tests: 7 for `recipe_needs_source`, 1 for the wrong-shape model.
